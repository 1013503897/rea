# Code-friendly tool design: exploratory results

Tracking: [#4063](https://github.com/morluto/rea/issues/4063).
The typed data interface worked on a real shipped Electron application. Merely
wrapping tools in code did not reliably produce composition. An adaptive
interface correction finally produced a genuine SDK aggregation on identical
retained input. This is a useful feasibility signal, not an efficiency claim.

## What was implemented

- A canonical typed module-reference view shared by CLI and MCP, with exact
  filters, canonical identities, retained range counts, observation support,
  independent source coverage and original Evidence links. Original item reads
  remain available. No second JavaScript parser was added.
- An experimental typed client and narrow discovery generated from named
  canonical schemas. Normal async/await and iterators work in the isolated
  experimental host. Production REA gains no arbitrary execution tool.
- Reproducible preparation, grading and retention scripts, plus authenticated
  public bundle import/export for an exact-snapshot follow-up. Applications,
  captures, generated full Evidence and the temporary bundle are not archived.

Sources sampled at `2c2c8df8d` (typed pilot) and `dec85f4cf` (adaptive follow-up).
Driver fingerprints and original executed-source snapshots are retained.

## Real applications and verification

The Electron question reviews external references in the actual published
Obsidian 1.14.4 `main.js`, selected with `package.json` from its ASAR. The browser
question groups all 39 requests in an owned empty-profile startup capture of
the actual public Excalidraw application. These are public application tasks,
not CTFs, synthetic applications or demonstration benchmarks.

The Obsidian oracle checks consistency against separately retained producer
items, not independent semantic extractor correctness. HAR grouping is decoded
independently from the original capture. One recorded status `-1` is an
unfinished capture entry, not an HTTP status or a proved server failure.

The executed real MCP verification matched all 23 selected module identities,
the ten external specifiers and every retained range count against original
item facts. Partial coverage and 36 unselected files remained explicit. Four
SDK pages, early iterator exit and missing-parent failure also passed.
Legacy page plus item replies were 338,208 structured bytes; the new reference
query was 23,402 bytes. This establishes representation and call-count changes,
not agent token savings. First retained-query round trip was 101 ms; two repeated
reads were 12/15 ms. No new query cache was introduced, and these are not cold
artifact-analysis timings.

See [executed boundary metrics](results/verification/real-obsidian-query.json).

## First typed-interface cohort

One counterbalanced pair per task; direct batches were permitted. Both arms
used the same runtime, artifact/capture inputs and available tools. Fresh
Obsidian analyses produced different parent IDs because dynamic parent result
budgets differed; selected question facts agreed. This cohort therefore does
not establish full-snapshot equivalence.

Observed failures matter:

- Obsidian code expected `Result` from a raw Evidence-returning call and threw
  the successful reply as an error. It then manually returned eleven external
  modules alongside a correct ten-entry dictionary. This fails correctness.
- Excalidraw code only printed replies; it did not programmatically group
  records. JavaScript-only narrow discovery and invalid selectors caused extra
  work. Passing facts therefore do not establish successful code composition.
- Direct completed both tasks. This small cohort does not support a code-mode
  advantage. Its failed code task earns no efficiency credit.

## Adaptive exact-snapshot pair

The next opt-in profile makes generic code calls and SDK methods consistently
return `Result`; it also keeps complete discovery for capture tasks. Both arms
imported the same authenticated 1,076,410-byte temporary bundle, SHA-256
`130b59412d2aa4613cf6b095039642e4e397969f6ab764e699bbe985a2673b6d`.
Snapshot preparation cost 64.512 s (scope wall 64.914 s), 49.049 family CPU seconds
and 1,079,283,712 peak bytes, once before the comparison.

Both arms produced byte-equivalent structured query Evidence:
`ev_faea596d8c9779fd463185bad16bcba6faa1acda9bb77df2446c109a9c4c9204`.
The parent, filtered rows, query parameters, provenance and coverage matched,
not just the requested scalar answers. See the [parity assertions](results/verification/shared-snapshot-parity.json).

| Arm    | Correct | Input / uncached | Output | Largest request input | Answer seconds | Preparation seconds | Family CPU seconds |    Peak bytes |
| ------ | ------- | ---------------: | -----: | --------------------: | -------------: | ------------------: | -----------------: | ------------: |
| Direct | No      |  50,946 / 50,946 |    621 |                22,205 |         63.888 |              11.739 |             16.797 | 1,085,665,280 |
| Code   | Yes     |  45,898 / 45,898 |  1,224 |                16,831 |         43.770 |              11.077 |             15.920 | 1,082,523,648 |

Each used three model rounds, one discovery action and two backend calls
(import plus query). The code used `rea.javascript.fromEvidence(...).modules.references`,
filtered the identity union, summed retained ranges and computed
`Object.keys(...).length`. Its cell completed and printed selected derived
facts with actual supporting IDs. This was genuine computation over records.
Direct returned the same ten-entry dictionary but claimed eleven external
modules; that answer fails. Neither answer claimed runtime loading.

No completed-task speedup can be inferred from a failed baseline. This is one
adaptive pair with different individual model samples, not repeated evidence
of superiority. The snapshot and interface changes are combined, so differences
between cohorts cannot isolate either cause. Post-correction network-agent
behavior has not been measured. No more samples were added to chase a win.

Full records: [shared-snapshot pair](results/2026-10-15-shared-snapshot/).
A missing reporting-only `oracle_scope` field was repaired after sampling;
task/oracle bytes, snapshot, model protocol and executed drivers were unchanged.

## Costs, retention and limits

All trials used local Codex CLI 0.161.0, configured `gpt-5.6-terra`, high reasoning,
and the controlled external JSON action protocol. Scored trials had zero native
tool calls. This measures that protocol, not native Codex MCP versus native
code-host latency. Replayed instructions, schemas, intermediate values, errors
and final output all contribute to recorded input/output usage. Model/provider
latency and cache variation are not controlled by the local CPU limit.

An earlier operator-aborted attempt overlapped a pre-push check. It is preserved
[separately](results/2026-10-15-typed-interrupted/): at least 13,646 input (7,936
cached) and 53 output tokens, 57.311 s trial wall and 22.900 family CPU seconds.
Usage from the cancelled in-flight turn is unobserved; total cost is incomplete.
It is not silently dropped or counted as a successful task.

Heavy jobs ran serially apart from that disclosed overlap. The supervisor used
one CPU affinity, 8 GiB cap, 6 GiB early stop, no swap and a host-memory reserve.
All recorded scopes reported no OOM and verified payload cleanup. CPU and peaks
above are kernel cgroup observations at verified payload exit, including small
observer overhead; vanished final whole-scope counters remain unknown. The
largest recorded local static/pre-push check peak was 6,304,075,776 bytes (about 5.87 GiB), below the 6 GiB early stop.

The original eight-trial pilot and two-trial dependency follow-up are retained
as separate historical cohorts, not a randomized third arm. Their runtime,
discovery and wording differ; no causal token ratio against them is claimed.
Executed-source snapshots preserve the earlier measurement-only driver change.

Saved records contain tasks/oracles, actual model actions and CLI events/usage,
answers, failure diagnostics, response digests, source fingerprints and resource
receipts. They contain no downloaded applications, raw HARs, full regenerable
producer payloads, profiles or credentials. Some diagnostic prefixes explicitly
omit dumped full Evidence while retaining its byte digest. Archive manifests
remain byte-stable. A rerun creates new snapshots/captures and new digests; the
original transient parent cannot be reconstructed byte-for-byte from a live
site or dynamic budget alone.

## What this supports next

Keep the shared typed data boundary and consistent code-result convention as
candidates. Measure repeated, preregistered completed tasks before choosing a
default interface. Include a controlled legacy-direct arm on the same snapshot
to isolate data-interface gains, then separate SDK/discovery choices. Additional
IPC/source joins and richer browser workflows remain unmeasured. Dossier and
retained-report organizations should be separate factors with the same facts.

Executed validation: 135 focused source/service, CLI/MCP, bridge and schema-profile
tests; SDK declaration generation/typechecking; build, static checks and generated
documentation checks. These do not establish live Electron runtime, debugger,
protection recovery, or large-capacity performance. No production integration
or broad code-mode efficiency conclusion is proposed by this experiment.
